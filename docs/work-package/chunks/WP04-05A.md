## Produced outputs/interfaces

`createPreferenceController({ initialCommitted, enqueue, applyLivePreferences, broadcastSilence })` exposes `getStatus()`, `subscribe(listener)`, `setAudioPreferences(intent: AudioPreferenceIntent)`, `setProfilePreferences(profileId, patch)`, `acceptCommitted(snapshot, acknowledgedGeneration?)`, `receiveSilence()`, and `flush()`. This helper has no database import. `enqueue` is the frozen async command port later bound by WP04-04A. Under DEC-026, `applyLivePreferences(intent): void` is the synchronous injected adapter to WP02-01A's `LiveAudioGate.applyLiveIntent(intent)`. Consume its AudioPreferenceIntent union (enable / exit-silence / silence-all / channel-mute / channel-volume); do not duplicate it. Call the gate before deriving/enqueuing narrow changed preference leaves. The full InstallationAudioPreferences stays solely in WP04. Exit-silence preserves channel mutes/volumes; a never-enabled installation requires enable. WP02-05A supplies playback later; no completed audio runtime is an incoming prerequisite.

PreferenceStatus is `{ requestedAudio, requestedProfileById, loadStatus: "loading" / "loaded" / "read-failed", generation, savedGeneration, pending, failed, errorCode? }`. WP01's subscription adapter forwards it to WP02.applyPreferenceState; that callback cannot enqueue another save. Generation is an in-tab monotonically increasing counter, not a stored cross-tab ordering timestamp. Track dirty leaf fields and the generation carried by each dispatched patch; an acknowledgement clears only fields not edited since that dispatch. Revision/epoch governs cross-tab authority. A fresh read replaces clean committed fields but not newer dirty fields or the live silence latch. Conflict retry reapplies only current dirty fields to the fresh token. Preference retries are distinct from educational-command conflicts, which require renewed Check intent.

On save failure retain requested state and a retry action; flush returns readiness with failed/pending preference reasons rather than clearing them. `receiveSilence()` synchronously latches all channels and invalidates pending activation/narration; incoming data contains no profile identity. Reconciliation never broadcasts unmute. If another tab explicitly resumes saved sound, already-latched tabs remain silent until their own deliberate exit; on cold start the latest committed preferences apply with browser activation checks. During import/reset/deletion, discard stale-epoch pending patches, retain live silence, refresh preferences, and report any unsaved choice rather than silently applying an old patch to the replacement household. Controller/WP02 asynchronous load/resume callbacks always consult current generation/latch, never captured settings.

**Required audio preferences (REQ-015/016, DEC-004):** installation-wide `InstallationAudioPreferences = { soundEnabled, silenceAll, music: { muted, volume }, effects: { muted, volume } }`, volumes in [0,1]. Initial `soundEnabled=false`, `silenceAll=false`, channel levels .25/.50 and channel mutes false; the enable gate makes the first visit silent until the dedicated Enable sound action. A generic Start/play gesture, slider adjustment or narration preference cannot enable sound. Saved enable consent still requires WP02's browser-compatible activation; never treat consent as permission to bypass persisted silence. Silence all persists, stops music/effects/current and queued speech immediately, and exits only through an explicit Resume sound action. Channel sliders never unmute or clear Silence all. Volume zero is silent; mute preserves volume. WP02 owns controls/playback and immediate Stop reading; profile narration starts off and navigation/resume cannot restart stopped narration.

Every slider/mute/Silence all action first calls WP02's synchronous live audio gate, then queues persistence; no `await` before silence. Tag requested changes with a monotonically increasing in-tab generation and coalesce rapid sliders to the latest changed fields. Save acknowledgments/refreshes for older generations cannot replace a newer live request. A stale preference write refreshes committed state and retries only the latest explicit fields; it cannot replay an old whole-save snapshot, implicit unmute or old consent. A live local/received Silence all latch remains set until explicit user exit, even if saved data is older or the write fails. Broadcast Silence all immediately to other open game tabs; saving it remains atomic through the same repository. Failure shows “Changed for this visit; couldn't save. Retry” and keeps requested silence through navigation/resume; update readiness stays false. On cold-start unreadable preferences stay silent. Preview requires explicit intent and enabled, unsilenced channels; hover/focus never plays.

Profile settings persist instructionReadAloud=false initially and motion=system/reduced. Routine narration is not Check/Hint; assessed-passage/order reading records WP03 support, explicit answer help is Hint. Essential text remains. Expose requested generation/pending/failed/savedGeneration plus flush/readiness, no second persisted preferences store.
