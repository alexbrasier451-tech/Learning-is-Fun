## Target outcome

Keep a labelled Sound button visible in the game shell, including activities and overlays. It opens independent Music and Effects on/off toggles and 0–100% sliders with keyboard/tap-adjustable values; volume zero is silence. Provide a directly reachable Silence all action that immediately stops/mutes music, active/queued effects and speech, plus a Stop reading action beside active read-aloud. Neither needs adult access. Changing volume never unmutes a muted channel; only explicit channel enable changes that channel's mute. Exit Silence all clears the global latch while preserving both channel settings. Narration does not override Silence all.

DEC-004 requires installation-wide music/effects mute, volume, sound enable and Silence all preferences within this browser's app namespace, loaded before playback and persisted by WP04. Switching profiles cannot defeat silence. Instruction read-aloud is initially off per profile and every utterance is user-triggered; reduced-motion preference is per profile plus system preference. First visit is silent until an explicit Enable sound action; initial enabled levels are music 25% and effects 50%. These are relative mix settings, not physical loudness guarantees. An ordinary gameplay tap is not consent to enable sound. Reload/navigation/resume/update apply preferences before playback; browser denial exposes an explicit retry. Hide/background pauses music and cancels effects/speech; resume never replays queued effects or narration. A failed preference read starts silent; a failed write preserves the live requested value and reports uncertain persistence. Silence all is a persistent latch with an explicit Exit Silence all action; sliders, channel toggles and Read aloud cannot clear it.

## Produced outputs/interfaces

**One audio owner/control contract.** WP01 creates one createAudioController({assetResolver, persistPreferences, speechAdapter}) outside routing. WP02 owns playback and its immediate live gate; WP04-05A owns requested preference generations, field coalescing, durable writes and cross-tab synchronization through WP04-04A. Do not add a second preference queue in WP02. Scenes/UI never create separate contexts/players/speech queues. InstallationAudioPreferences is WP04's {soundEnabled, silenceAll, music:{muted,volume}, effects:{muted,volume}}, volumes 0–1; initial false/false/unmuted/.25/.50 remains behind the disabled gate. Preferences must report loaded/read-failed before playback. Every control updates the live gate before invoking persistence; stale acknowledgment cannot reinstate older audible settings. Per-profile read-aloud starts off and cannot bypass the installation gate.

Commands: enableSoundFromGesture, setChannelMuted, setChannelVolume, silenceAll, exitSilenceAllFromGesture, setSceneTheme, playEffect, readText, stopReading, setVisible, dispose. Subscription exposes channels/latch/loading/blocked/persistence/speaking status to one panel. Enable changes soundEnabled/browser activation only, preserving stored channel mutes/levels. Exit Silence all explicitly clears only that latch; it never unmutes channels, changes levels or replays speech. Sliders/toggles/read-aloud cannot clear it. Ordinary gameplay gestures never enable first sound.

Playback requires loaded preferences, explicit soundEnabled, no silence latch, visible page, permitted/resumed context and channel unmuted with nonzero volume. One Web Audio graph has music/effects buses/master gain; per-track gains allow at most two sources during a brief theme crossfade. [AudioBufferSourceNode](https://developer.mozilla.org/en-US/docs/Web/API/AudioBufferSourceNode) loops decoded buffers with single-use source nodes; [GainNode](https://developer.mozilla.org/en-US/docs/Web/API/GainNode) mixes channels. Track active sources/cancellation generation. Silence all immediately zeros output, cancels gain schedules, stops/clears current/scheduled sources, invalidates old callbacks and cancels speech; no fade/storage wait. Fetch/decode/resume/end/fade callbacks recheck generation/current policy before output. Channel mute stops that channel; volume zero stays silent; no queue survives hide/scene teardown. WP01 supplies visibility/disposal; [autoplay denial](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Autoplay) exposes explicit retry without defeating silence.

Speech is outside the Web Audio graph: master gain alone cannot silence it. Enumerate English voices and use only those reporting [localService](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesisVoice/localService); absent local voice yields visible-text/unavailable state. This is feature detection, not a platform-wide network guarantee; WP01 verifies local-data behaviour. readText requires explicit enable/no global silence plus WP03 classification; otherwise show enable/exit controls without speaking. One utterance/no queue; [cancel()](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/cancel) stops pending/current speech on Stop, Silence all, hide, route/profile switch or disposal. Utterance tokens prevent stale end/error callbacks restoring music or starting narration. Speech ducks current permitted music, then restores only current policy; it never changes stored volume. Assessed-text/answer-help speech records WP03/WP04 assistance before speaking; instruction narration is not a hint. Stop reading stays visible outside overlays.

persistPreferences delegates through WP04's preference controller to its sole createStateController dispatch; no second queue or durable facade. Use DEC-017 committed/already-applied/invalid/conflict/save-failed/unsupported vocabulary.

**Accepted consuming port (DEC-026).** `persistPreferences(change: AudioPreferenceIntent)` delegates to WP04-05A `setAudioPreferences(intent)`, which alone owns generations/queue and enqueues through the facade. Controls send explicit intent; they do not directly dispatch SetAudioPreferences. WP04's injected `applyLivePreferences` callback binds to this controller's `applyLiveIntent(intent): void`, synchronously applying the music/effects/speech gate before enqueue or any await. There is no second audio method/queue named applyLivePreferences. Receiving a gate intent is idempotent and never echoes persistence. Only explicit exit can clear a latch. `applyPreferenceState(status)` consumes WP04-05A's exact PreferenceStatus including loadStatus; acknowledgments cannot override a newer live request. WP01 binds the subscription and forwarding callback. WP02-01A owns the early pure intent port; WP04 owns full preference/status fields, preserving DEP-041/042 without a state→completed-audio prerequisite.

AudioController exports the named commands above plus `getSnapshot(): AudioStatus`, `subscribe(listener): () => void` and those adapter methods. `setChannelMuted(channel, boolean)`, `setChannelVolume(channel, number)` and `silenceAll()` send preference intent through the synchronous port before returning. `setSceneTheme('village'|'library'|null)`, `setVisible(boolean)`, `stopReading()` and `dispose()` change playback only. Gesture methods may await context resume, but live gate/consent changes occur first and continuations recheck generation/policy. `playEffect(cueId)` drops disallowed requests immediately, never queues for later. `readText({requestId,text,role,language:'en'})` accepts only caller-authorized visible text; QuestActivity commits required assistance first. AudioStatus contains live preferences, load state (loading/loaded/read-failed), activation (inactive/ready/blocked/unavailable), speaking boolean, local-voice availability and WP04 persistence status. AudioControls takes `{controller}`; StopReading subscribes to that same controller. No component invents saved success.

`createSpeechAdapter()` supplies local voice enumeration, one active utterance and cancel/dispose; runtime checks actual `localService` and English language before speaking. An assessed-reading record marks listening support; it is not automatically an answer hint. WP03's classification decides whether a separate answer-help flag applies. Navigation/profile change calls stopReading and cancels scene effects/motion before mounting another activity; changing the scene theme does not clear mute/consent/latch.

## Acceptance criteria

1. **Reliable user control:** At PC/tablet layouts, independently set Music off/Effects on and the inverse, adjust each slider, set zero, and invoke Silence all while a restoration and read-aloud are active. The current sound stops without waiting for a track/effect to finish; no queued cue escapes. Verify the chosen silence/levels through scene navigation, profile switch, reload, background/foreground and update. Verify controls from an activity overlay and with keyboard; Stop reading cancels current/queued speech. Returning to sound requires explicit user intent and preserves the other channel's settings. Initial activation/blocked-audio fallback and any save-preference error remain honest. WP06 records what was actually heard separately from technical verification.

2. Fresh/failed-load silent; explicit enable preserves channel/latch/levels and cannot exit Silence all.
3. Synchronous silence cancels gain schedules/sources/utterances/generations before persistence; stale callback cannot re-enable output.
4. Hide/route/profile/dispose clears speech/effects; resume never replays queues. Failed/out-of-order acknowledgment cannot restore older audible state.
5. No local English voice means text/unavailable fallback; graph gain cannot substitute for speech cancellation. Duck/end respects current permitted policy.
6. Muted/unavailable states never block play or hide instructions.

7. Early construction uses fakes, but producer completion demonstrates real WP04 load/dispatch/save status with real seven-file exports in the minimal host. One mounted control panel and one controller serve scene requests; rerender/navigation does not create another context or speech queue.
8. Starting silent, perform explicit Enable sound, independent channel changes, Silence all, slider/channel changes under the latch, then explicit Exit Silence all. Verify that the exit preserves channel settings and never restarts speech. A regular game tap, volume change, delayed decode/resume or successful older save cannot make disabled/latched output audible.
9. Real preference failure immediately preserves the requested live silence, shows uncertain persistence and permits safe retry of the latest snapshot. Read failure stays silent. Source listening and published listening remain separately recorded; this chunk's fake-event checks do not satisfy acoustic acceptance.
