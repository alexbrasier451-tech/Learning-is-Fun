## Target outcome

**Free tooling route and assessed limits.** Reuse the connected agent browser for visible DOM/keyboard/click interaction, screenshots and qualitative play; reuse project-local [Playwright Test](https://playwright.dev/docs/intro), [Apache-2.0](https://github.com/microsoft/playwright/blob/main/LICENSE), for exact engine/input/offline/clock scenarios and traces. Use the single WP01-owned configuration. Its current maintained [emulation API](https://playwright.dev/docs/emulation) supports viewport, touch context, reduced motion and timezone; [WebKit is not Safari](https://playwright.dev/docs/browsers#webkit). This avoids writing an automation framework or buying a browser/device service. Test binaries must match the project's pinned Playwright; installation and launch smoke are future execution preparation, not work done now.

On 8 October 2026, read-only tool inventory found a connected Codex in-app browser with DOM snapshots/locators, screenshots, keyboard/click and width/height viewport override. Its documented API exposes no engine selector, touch input, offline/clock control or audio capture; do not invent those capabilities. No game tab or playtest was started. WP01's host inventory confirms Node 24/Playwright 1.62.1 and Chromium file presence; Firefox/WebKit files are absent, Edge is present and a branded Chrome channel is still to be confirmed. That is a viable free setup route, not proof all D1–T2 engines launch today.

**Touch evidence route.** Playwright's [Touchscreen API](https://playwright.dev/docs/api/class-touchscreen) provides taps only. For T1, use `hasTouch: true` and a small Chromium-specific test helper sending `Input.dispatchTouchEvent` start/move/end/cancel through a Playwright CDP session. The [official protocol schema](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/browser_protocol.json) exposes these events. Capture the resulting `pointerType: 'touch'`/cancellation and visible construction without bypassing the actual WP02 Pointer Events handlers. Test tap alternatives with touchscreen taps, not `mouse.click`. T2 uses WebKit's supported touch taps for all activities/portrait/rotation; T1 supplies the required touch-drag evidence. Synthetic [legacy TouchEvent dispatch](https://playwright.dev/docs/touch-events) does not establish trusted Pointer Events/pointer-capture behaviour, so it is neither a substitute nor a reason to add a legacy-touch implementation to WP02. If a later requirement demands trusted WebKit dragging too, report that particular capability gap to Controller; no physical-device requirement is added implicitly.

The agent must still inspect current rendered UI/screenshots, choose responses and record observations during D1/T1. A deterministic journey/trace is supporting evidence, not an automatic claim that an agent explored usability. Where the connected browser cannot drive a matrix mode, the future executor uses the checked-in Playwright test harness for bounded UI actions/checkpoints and assesses its visible outputs before choosing the next steps; keep this within supported task tools. If the execution host cannot support such agent-directed interaction, that full-journey case remains blocked rather than being relabelled as passed from a fixed script. Do not create a remote agent gateway or production answer/progression hooks.

**Audio evidence route.** Current browser tooling has no advertised listening/loopback capture capability. Playwright screenshots, trace/video and playback/gain checks are technical evidence; they do not prove audible quality or acoustic silence. Establish a capable listener/capture route during execution or record the gap. Earlier WP02-03A source listening can support unchanged asset quality, but published control/mix evidence is still needed. Observers supply their available recordings/results to the later WP02-12A/13A criterion reviewers; those reviews cannot be prerequisites for this foundation. Otherwise audible review remains explicitly unverified and overall audio acceptance remains pending. No paid service is a dependency.

Keep emulation, physical devices and child sessions separate. Physical-tablet/child sessions are not package gates; no educational-efficacy or child-enjoyment claim follows from agent observations.

## Produced outputs/interfaces

Report rows use the following evidence-only schema, defined here once and reused by all observers and WP02 reviews. These are not production DTOs or extra coverage IDs.

| Field | Meaning |
|---|---|
| `scenarioId`, `release`, `candidateUrl`, `candidateBuildId` | Stable scenario label, M1/M2 and exact candidate identity from WP01; verify visible identity before actions. |
| `matrixCase`, `browserVersion`, `viewport`, `inputMode` | D1–T2, actual engine/version, CSS width/height and keyboard/mouse/touch route. Record OS and emulation/device class in the session header. |
| `seededOrUnseeded`, `setupRef`, `actions` | Fresh normal UI journey versus controlled fixture, its provenance/clock settings and actual agent-selected actions. No hidden setup. |
| `expected`, `observed`, `status` | Producer criterion/value reference, concrete observed result and passed/failed/blocked/untested. Missing evidence is never a pass. |
| `evidenceLinks`, `acousticStatus` | Retained screenshots/trace/DOM/recording references; acoustic verified/unverified where required, otherwise not-applicable. A filename is not listening evidence. |
| `defectOwner`, `retestedBuildId`, `finalBuildApplicability` | Causal owner or unresolved routing, corrected candidate if retested, and either direct final-build evidence or named unchanged-scope rationale. Use null when no defect/retest applies, not fabricated values. |

`recordCheckpoint(page: Page, testInfo: TestInfo, row: CheckpointRecord): Promise<void>` attaches the metadata, current screenshot and concise observed visible state to the existing Playwright report. It records observations without computing a pass or choosing a next answer. `touchDrag(page: Page, {from: {x,y}, to: {x,y}}): Promise<void>` sends start/intermediate move/end in viewport CSS coordinates selected from current rendered targets; `touchCancel(page: Page, {from, toward}): Promise<void>` ends with cancel instead. Both require a Chromium touch context, release contact/session in finally and reject unsupported engines explicitly; they never mutate a response draft or synthesize a Check. These helpers stay test-only.

SCENARIOS maps M1-ENTRY/Q1–Q3/ACCESS/LOCAL/WEEK/OFFLINE/AUDIO/VISUAL and M2 Q1–Q10/new-mechanic cases to owner expectations and D1–T2; labels are test labels, not new coverage IDs. Each case names seeded/unseeded setup, controls, checkpoints, expected owner result, evidence class and causal owner. `recordCheckpoint` attaches metadata/selected screenshot/observed DOM to Playwright report/trace rather than inventing another reporter. Evidence paths are `artifacts/playtests/<release>/<build-id>/<case>/`, excluded from dist.

SCENARIOS also names M1-PRACTICE-LIFECYCLE and M2-UPGRADE-CONTINUE. Under accepted DEC-024/025 consume [WP04-01A's command/episode definitions](WP04-01A.md#produced-outputsinterfaces) and [WP03-01A's discriminated observation definitions](WP03-01A.md#produced-outputsinterfaces): leaving suspends without emitting completion; deliberate unsuccessful finish produces one episode completion, while canonical/encounter/opportunity identity and cumulative attempts/assistance/earning week persist. The scenarios assert those meanings through UI, normal export and owner expected results, never copy command types into the harness. Completion-only observations contain no new Check/submission; their event identity derives from the existing actionId, and returning can increment episode ordinal without renewing reward eligibility. Preference/audio scenarios consume DEC-026's producer ports; early-host checks consume DEC-027's WP01-01A definition.

Keep scenario definitions and expected results separate from run observations. In D1/T1 the agent records a rendered checkpoint, selects a bounded supported UI action, observes the result and then selects the next action. Retain this action/observation sequence in JOURNEY; running starter.spec.ts alone is explicitly insufficient. The rehearsal must establish a usable supported step/pause/resume route before declaring toolkit readiness; if task tools cannot provide it, record a capability blocker, not a custom remote gateway.

## Acceptance criteria

1. D1–T2 scenarios use the [single platform matrix](WP01-01A.md#target-outcome) and actual project config with recorded engine/version/input; Chrome evidence is branded Chrome, WebKit evidence is named emulation rather than Safari.
2. An agent can inspect rendered checkpoints and choose the next bounded action in required D1/T1 modes with supported task tools. A fixed script passing alone cannot satisfy the journey. Unsupported route leaves the mode blocked.
3. T1 helper produces observed `pointerType: touch`, real visible manipulation and cancellation through WP02 Pointer Events; touchscreen taps exercise alternatives. T2 taps/rotation are supported; legacy TouchEvent dispatch is not trusted-drag evidence.
4. Report schema preserves build/URL/environment/actions/expected-observed/status/evidence/owner/retest/final applicability and separate audible verified/unverified value. No absent artifact, video filename or playback event implies listening.
5. Claims distinguish emulation, real devices and children; toolkit readiness never asserts an integrated game pass.
6. A readiness table names each required mode's actual engine, launch, agent-observation/action route, input and unavailable capabilities. Rehearse agent choice at a visible D1 checkpoint and a T1 touch manipulation/cancel checkpoint in the early host. Separate host readiness from later published-game success; an existing binary or mouse-resized window never fills a missing mode.
7. Scenario metadata distinguishes required two-loop/five-effect listening from technical mute/gain checks, and names how two loop joins per track and every cue will be observed. A sample attachment records an intentionally unavailable listening route as unverified without converting the whole fixture rehearsal into a false release pass.
