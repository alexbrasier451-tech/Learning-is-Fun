**Accepted early active-panel contract (DEC-027/033).** `src/app/panelLifecycle.ts` has no runtime, React, state or domain imports. It owns only the following types; WP02 implements the activity adapter, WP01-02A implements the registry/guard, and the fixture host can supply a small recorder implementation.

```ts
type ActivePanelStatus = Readonly<{ dirty: boolean; pending: boolean; failed: boolean }>;
type PanelLeaveResult = { status: 'ready' } | { status: 'blocked'; message: string };
interface ActivePanelLifecycle {
  getStatus(): ActivePanelStatus;
  subscribe(listener: () => void): () => void;
  suspend(): Promise<PanelLeaveResult>;
  discardDraft(): PanelLeaveResult;
}
interface ActivePanelHost {
  register(panel: ActivePanelLifecycle): () => void;
}
```

`dirty` means a transient draft differs from its last committed reconstruction; `pending` covers a command/suspension that must settle before leaving; `failed` keeps an unresolved suspension/leave failure visible even if the draft comparison alone is clean. Status is stable until a relevant change, and notification is synchronous when these flags change. `suspend()` invokes the producer's existing suspension command and reports ready only when the panel can leave without losing its draft; blocked/rejected work keeps the panel/draft and reports a child-readable message. It never finishes practice or resets committed attempt/help/reward facts. `discardDraft()` is called only after explicit user choice; it discards only transient edits, returns blocked while work is pending, and cannot cancel or roll back a committed/in-flight command. WP02 owns mapping its actual CommitResult and epoch/profile checks into this UI-only result.

`register` returns an idempotent unregister closure tied to a fresh opaque registration token. The shell subscribes to the registered panel and reads its initial status before considering readiness. Cleanup unsubscribes that registration but clears the active slot/readiness only if its token still matches; stale cleanup or notification cannot remove/change a newer panel. A new panel may replace the old one only after a successful guarded transition or explicit teardown of the same binding; an unexpected replacement while old work is dirty/pending/failed fails closed. An unregister callback is cleanup, never authority to discard a dirty draft or mark a failed transition safe. Domain selection and profile/epoch identity stay in the producer/shell adapters, outside this early type.

- `APP_ID = 'learning-is-fun'`; `BASE_URL = import.meta.env.BASE_URL`; `APP_NAMESPACE` combines APP_ID with the normalized deployment base path. WP04 uses this namespace for its store; WP01 uses it for cache names. Derive the namespace once and keep it stable across build IDs. Vite `base` is the supplied `/<repository>/` (or `/` for a confirmed root/custom-domain site), with leading/trailing slash. Static public URLs use `assetUrl(relativePath)`; imported assets use Vite URLs. No root-literal `/assets/...` or remote gameplay dependency. [Vite Pages guidance](https://vite.dev/guide/static-deploy.html#github-pages).

`assetUrl(relativePath: string): string` accepts an app-relative path with no leading slash, scheme, query/fragment or `..` traversal and returns a BASE_URL-prefixed URL; callers use imported Vite URLs as-is. Normalize configured base once; reject malformed base instead of silently falling back to `/`. APP_NAMESPACE is `${APP_ID}:${BASE_URL}` within browser origin storage, stable across builds. BUILD_ID is a supplied candidate identity embedded consistently in app and worker; CI uses commit plus workflow run/attempt, while local builds use an explicitly marked local identity.

Separate a local fixture/base-path project from published-observation projects; a published run requires an explicit HTTPS URL and must not silently fall back to localhost.
