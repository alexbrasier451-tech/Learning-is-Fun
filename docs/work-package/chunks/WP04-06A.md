## Produced outputs/interfaces

Panel ports: `ProfileChooser({ snapshot, selectedProfileId, dispatch, onSelectProfile })`; `AdultArea({ snapshot, selectedProfileId, preferenceController, dispatch, backupActions, onExit })`; `ProgressView({ profileIdentity, summaries: readonly LearningSummary[] })`; `BackupPanel({ backupActions, saveStatus })`. WP01-02A's shell adapter supplies ports; focused host adapters supply actual WP04 state before shell composition. Profile selection is tab navigation, not a persisted active-profile field. The panel cannot change a pending command's captured profile ID. `backupActions` wraps facade-controlled export/prepare/cancel/confirm; panels never call repository writes or manufacture validated data. Subscribe through the shared external-state port and unsubscribe on unmount; UI pending/error state is transient.

Under DEC-033, onSelectProfile requests the shell-owned guarded switch; the chooser does not optimistically replace selectedProfileId or retarget pending callbacks. The shell completes the currently registered panel's suspension or explicit permitted discard before publishing the new tab selection, including the explicit selectedProfileId input to WP02's M1/M2 adventure adapters. Blocked leave retains the old view, selected identity and draft. Deletion/import that removes the selected identity returns through shell selection/recovery; it never silently selects a different child for an in-flight command. Reuse the existing pending-action/profile-switch case for this adapter.

Chooser uses illustrated avatar IDs supplied by WP02-02A, nickname trim/1–24-character validation and supported capacity 16. ProgressView renders WP03 summarizeLearning output; it does not recalculate counts or classify ability. Selection/reset/delete buttons have typed busy/conflict/failure states; refreshed confirmations must show the new token's actual affected identities before reissuing destructive intent. Browser download/import File handling lives in BackupPanel with the decoder's pre-read size check. Dialogs/sections use native labels, focus entry/return and keyboard/touch routes; retain the storybook paper/ink/illustrated-avatar visual language instead of generic dashboard placeholders. Expose immediate audio controls through the existing shell, never behind grown-up entry.

**Adult entry:** a visible “For grown-ups” link opens a short explanatory screen and a separate “Continue to adult area” action. No timer, arithmetic challenge, password, PIN or identity claim. It is an accidental-entry barrier, explicitly described as such. Leaving the adult area closes it; every destructive action still requires its own confirmation. Keyboard and touch access follow WP02's contract.

**Progress view:** select one local profile; show each encountered skill with recorded Check count, unassisted first successes, supported/later successes, hints used, recent supported misconception feedback and latest review result/date where available. Show “not practised” or “not enough evidence” for absent evidence. Distinguish observed performance from due/suggested practice. Do not label a percentage as ability, mastery certainty, a diagnosis or proof of retention. Explain that a delayed successful review is an observation, not proof of durable learning.

**Settings:** `ProfilePreferences = { instructionReadAloud: boolean, motion: "system" / "reduced" }`, initially false/system, persists across sessions. Routine narration/instruction read-aloud neither consumes a Check nor removes WP05 first-correct eligibility. Reading the passage/order under assessment is recorded as reading-supported evidence by WP03; it does not silently incur a points penalty. Explicit answer-relevant Hint is the scoring assistance flag. Keep essential text visible. The adult screen does not override accepted answers, scores, weekly cap or timezone; no difficulty selector for competitive farming.

Chooser captures immutable profile ID and edits nickname/avatar without account/email/birth date/real name. Explain browser-profile/origin/app-local scope, clearing-data loss and manual backup transfer. Destructive previews name target/all data, offer export and carry token. Display typed conflict/failure; never saved success before commit. BackupPanel consumes validation/preview/replacement, never JSON patches. No advertising/child purchases across this product surface; integration preserves the global constraint.
