## Acceptance criteria

1. **Visual finish:** Review the green, bridge, library and market, all three activity states, companion/planter UI and completion scene at the accepted desktop and both tablet orientations. Every reviewed surface must pass each category: coherent palette/material/character treatment; clear focal action; readable text/control hierarchy; crisp correctly scaled art; complete initial/selected/feedback/restored states; purposeful motion with equivalent reduced-motion presentation. Record concrete pass/fail observations, not only an aggregate beauty score. Missing assets, placeholder labels/art, illegible/clipped controls, mismatched stock styles and broken animation/state transitions fail the target.

2. **Integrated visual acceptance:** WP06 actually records observations from the published first-slice URL at the accepted layouts against these criteria. Every criterion-failing visual/interaction defect has an owner and is corrected and retested on the published candidate before this visual target is accepted; subjective enhancements beyond the criteria may remain labelled backlog. Device/emulation limits are explicit. Counts, screenshots or functional unit tests alone do not establish visual quality.

3. **Music/effect quality:** The published first slice includes both musical loops and all five cues, traceable to provenance. Listen through at least two loop joins per track and exercise each cue: no unintended gaps/clicks, clipping, stacked duplicate music, harsh feedback or speech masking. Movement between scenes changes themes cleanly and mute still works during transitions. If the agent cannot listen, retain technical checks but mark acoustic review unverified and hand it to an audio-capable reviewer; do not claim audible quality from callbacks or media state.

4. **Reliable user control:** At PC/tablet layouts, independently set Music off/Effects on and the inverse, adjust each slider, set zero, and invoke Silence all while a restoration and read-aloud are active. The current sound stops without waiting for a track/effect to finish; no queued cue escapes. Verify the chosen silence/levels through scene navigation, profile switch, reload, background/foreground and update. Verify controls from an activity overlay and with keyboard; Stop reading cancels current/queued speech. Returning to sound requires explicit user intent and preserves the other channel's settings. Initial activation/blocked-audio fallback and any save-preference error remain honest. WP06 records what was actually heard separately from technical verification.

5. Each required category/surface/control/acoustic result links to actual WP06 evidence for the identified candidate, with passed/failed/blocked/untested stated explicitly. A missing layout, inaudible tool, missing loop-join observation or unsupported input is never inferred as passed from another mode.
6. Where WP06 already observed a complete journey, reuse it and request only the missing state or listening observation. Corrected-build retests cover each criterion failure and the original affected integrated path; evidence clearly distinguishes old and corrected builds. Submit a criterion-closure recommendation to WP06-04A, not a separate release acceptance.
7. Confirm future agent play entered through the real GitHub Pages URL and exercised the complete first adventure at the DEC-005 PC/tablet coverage. Technical media state remains separate from actual heard music/effects/silence; unresolved listening leaves acoustic acceptance unverified.
