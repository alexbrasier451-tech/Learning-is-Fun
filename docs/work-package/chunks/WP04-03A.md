## Produced outputs/interfaces

`decodeBackup(text, catalogue): DecodeResult` returns `{ status: "valid", envelope }` or `{ status: "invalid" / "unsupported", issues: [{ path, code, message }] }`; it never writes. Check UTF-8 size and a bounded quote/escape-aware depth scan before JSON.parse, then count/validate values iteratively and construct fresh typed records. The File adapter checks file.size before reading; the decoder repeats the byte limit for non-File callers. `validateSave(candidate, catalogue): ValidationResult` is the synchronous full-root pre-write gate, including serialized envelope byte budget. `prepareImport(decodedEnvelope, currentSnapshot)` yields a readonly preview `{ preparedImportId, expected, exportedAt, profileNames, profileCount }` paired privately with the validated save; previews are transient, discarded after use/reload and reissued on token conflict. `exportBackup(snapshot, exportedAt)` yields `{ filename, json, byteLength }`; exportedAt is supplied by the controller, not a hidden clock. `migrateSupportedSave(envelope, targetContentVersion)` returns validated compatible data or unsupported, with v1 identity as the only initial schema path. No import operation reaches repository.ts before explicit replacement confirmation.

Validation ownership: WP03 validates canonical descriptor/response references and supplies evidence bounds; WP05 scoring checks award components/compact sums/open tracks, and standings checks archive/rank/aggregate invariants. WP04 joins these to profile/world/static catalogue references, episode/Check guards, preferences and capacity. Do not require raw history that producers intentionally compacted or treat historical snapshot names/informational IDs as live foreign keys. Completed-unsuccessful episode history may compact through WP03's evidence window, but its enclosing unresolved encounter, cumulative Checks/help and reward opportunity must remain. A decoder cannot advance reward completion marks to fit a file budget.

Validate saved bindingProvenance through WP03's retained compatible binding registry and world.completedStoryBindingIds through WP02's owning shape. Only story-role binding IDs enter the permanent set, and completed quests satisfy their retained required binding set without needing live completed encounter records. Optional transfer source validation uses its immutable singleton source definition plus permanent completion; no source encounter pointer or extra transfer-history store exists. Include source-encounter compaction before the existing backup round trip so a restored optional transfer still resolves, while malformed role/quest/task mismatches reject without mutation.

**Import/version bounds.** Reject files over 16 MiB before `file.text()`/JSON parsing; no ZIP, remote fetch, embedded media or executable data. Format v1 decode accepts JSON only, nesting at most 32, at most 250,000 visited values, IDs at most 160 characters, nicknames 1–24 characters and other text at most 4,096 characters; response/task fields additionally use WP03's stricter validators. Accepted household capacity is 16 profiles (meeting the required four); retain fixed 20-skill/ten-quest catalogue bounds and at most 52 displayed participating-week archives. Decoder builds fresh explicit records, rejects unexpected fields at versioned DTO boundaries, dangerous property names, duplicate IDs, dangling references, nonfinite/negative/noninteger counters, invalid dates/weeks, invalid enum/range preferences and unsupported schema/content/policy versions. Never render imported strings as HTML.

Semantic checks include component exclusivity and +5/+15/+5 amounts, slot uniqueness/count ≤30, weekly ≤600, lifetime sum of compact per-canonical award totals plus once-only quest totals, entitlement thresholds, unfinished attempt/hint consistency, archive ordering and referenced identities. Deletion-marked archives legitimately preserve original rank gaps; do not recompute them to “repair” an import. Historical nicknames/medal counts/personal bests and WP03 evidence include retained aggregates whose full event history is intentionally absent; validate their bounds/available provenance, without claiming cryptographic authenticity or recreating every event. Unknown catalogue IDs require an explicit compatibility mapping, not silent stripping.

After validation, preview profile names/count/export date and replacement loss; offer current export, then require Replace. Capture the current token for that preview; if it changes before confirmation, regenerate the preview rather than erase intervening play. Replacement atomically writes validated save under a new local epoch/revision; it never imports the old token or merges scores. Preserve imported logical weeks/state exactly; on the subsequent normal resume action apply current calendar policy, so the round trip and elapsed-time rollover are separately observable. Stop audio during replacement; loaded preferences cannot bypass that page's explicit activation/silence gate.

Payload v1 is the first format. Do not invent v0 migrations. Future supported adjacent migrations are pure decode/transform/validate operations followed by one atomic replacement; an exception leaves the prior root untouched. Unknown future payload/database versions are read-only recovery cases with existing bytes exported where the browser permits; never reset automatically. Keep IndexedDB structural version independent of content and save versions; WP01 cache cleanup never calls storage deletion. The 16 MiB bound is the accepted supported household budget, not permission to truncate saves: compact bounded recent evidence and receipts through the WP03/WP05 domain contracts, verify self-export/self-import below that limit, and fail any capacity-exceeding write before losing data with a backup/recovery message. Larger supported capacity needs an explicit format-policy revision, not silent acceptance.

Build original typed decoders for this fixed format; no new schema framework solely for backup. A shared validator library later chosen elsewhere is reused only under Controller-approved contracts. Fresh explicit records and text-only rendering avoid imported executable/HTML data.
