## Produced outputs/interfaces

`openSaveRepository({ appNamespace, initialSave, validateSave })` returns a repository with `loadRoot(): Promise<LoadResult>`, `commitCommand(command, { reduce, context }): Promise<CommitResult>`, `readExportSnapshot(): Promise<CommittedSnapshot>`, `replaceSave({ expected, validatedSave, replacementEpoch }): Promise<CommitResult>`, and `close(): void`. LoadResult distinguishes absent/new, ready, blocked, unsupported and unreadable. Initialization creates a default root only after a transaction confirms absence; two first-launch tabs cannot both initialize over each other. Reducer/validator are synchronous injected ports from WP04-01A; fixtures supply them here. The repository does not import later transition.ts or backup.ts. Invalidation subscription is a narrow callback carrying a new token or silence signal; no durable payload is carried in the channel.

Mutation ordering is epoch check → retained identical-delivery check → revision check → synchronous reduction → validation → put → tx.done. Duplicate recognition is read-only and domain-supplied; it may accept an identical retained Check/episode closure after intervening commits within the same epoch, but it cannot accept a mismatched payload or bypass epoch protection. All new writes require an exact token. New commits increment revision once; atomic reset/import writes the caller's fresh locally generated epoch with revision zero. If acknowledgement is lost, retry against the resulting epoch conflicts safely rather than applying replacement again. Absent/expired receipt is never permission to reapply. Revisions/ordinals must remain safe integers; exhaustion reports unsupported capacity before mutation.

`repository.ts` alone opens a `readwrite` transaction, reads `root`, checks epoch/revision and command preconditions, synchronously builds the complete next value, writes it, and awaits `tx.done`. Calendar closure, learning, score receipts, quest completion and cosmetics therefore either commit together or retain the prior root. Only IndexedDB requests may be awaited inside that transaction: content loading, JSON decoding, user confirmation and media work occur beforehand. Catch reducer exceptions and explicitly abort; never leave a queued partial write to auto-commit. [idb transaction guidance](https://github.com/jakearchibald/idb#transaction-lifetime).

Publish `CommittedSnapshot` and celebration changes only after completion. A transaction completion is the normal browser save acknowledgment; it is not a guarantee against operating-system disk failure or browser-data clearing. [IndexedDB durability notes](https://developer.mozilla.org/en-US/docs/Web/API/IDBTransaction). There is no localStorage fallback that creates a second save authority, periodic full-save timer, unload-dependent saving or durable event bus.

**Stale tabs and one writer.** Each tab has one state controller/serialized queue; the shared database's overlapping write transactions serialize across tabs. Read/check/write the token inside that transaction, not beforehand. A stale action returns conflict plus fresh state, preserves its response draft and asks for a renewed Check/confirmation; it never silently overwrites/rebases learning or destructive actions. A recognized duplicate in the same epoch can return already-applied without another award; old-epoch commands are rejected. WP04 encounter/check guards and WP05 reward component receipts protect against older duplicate delivery after intervening commits. Compacted encounter IDs are no longer executable: reject them as expired rather than trying to reconstruct a removed result. Retained latest/unfinished records support legitimate retry; completion high-water guards later selection/allocation.

Use a namespaced [BroadcastChannel](https://developer.mozilla.org/en-US/docs/Web/API/Broadcast_Channel_API) for committed-token invalidation and immediate Silence all notification, with no profile data in messages. Receivers reload from IndexedDB; broadcasts are notifications, not authoritative state. Missing/delayed messages cannot bypass the token check; resume/focus and pre-action reads refresh independently. No tab lease, heartbeat election or Web Locks requirement is necessary. A `blocking/versionchange` callback closes the connection and suspends writes; blocked upgrades show “Close other game tabs and retry”. A terminated/unreadable store offers recovery without opening a blank save.

Reuse native IndexedDB and a verified published idb 8.x patch, pinned and locally bundled; retain [API/transaction lifetime](https://github.com/jakearchibald/idb), [ISC licence](https://github.com/jakearchibald/idb/blob/main/LICENSE), [transaction scheduling](https://w3c.github.io/IndexedDB/#transaction-scheduling). Stage 6 saw upstream 8.0.4 metadata, which was not proof of registry publication. [Dexie](https://dexie.org/docs/API-Reference), [Apache-2.0 licence](https://github.com/dexie/Dexie.js/blob/master/LICENSE), is rejected: no query/live-query/cloud need. No ORM, lease election or localStorage fallback.

## Acceptance criteria

Reload recovers last commit. Abort/reducer failure leaves prior complete root. Two tabs cannot silently overwrite newer token; old epochs cannot alter replacement/reset. Adapter delegates duplicates to domain guards, never manufactures rewards. Blocked/versionchange/terminated/unknown-store states suspend writes and provide recovery rather than blank reset. Unrelated namespace is untouched.

Record paired root/token outcomes for a successful mutation, explicit reducer/validator abort after a write is queued, and two competing tabs starting from the same token. Only one conflicting mutation may win; the other returns conflict with fresh committed state. Deliver duplicate, missing-invalidation and old-epoch requests without a second mutation. A separate app-namespace sentinel survives reset/replacement. Queue/connection recovery must not fabricate an empty save or acknowledge a write before tx.done.
