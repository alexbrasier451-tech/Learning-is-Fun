## Structural validation and recovery

The delivered frozen records define a finite reviewed domain. A reconstructed record must retain descriptor, context, controls, all reviewed answers, objective/band/source, hints, worked support and narration. Presentation control order and positive revision may change without changing meaning or identity. Content validation first checks finite JSON types before any normalization: NaN must not become null, holes must not become array entries, undefined must not disappear, and a getter must not execute as content. Unknown identities, unreviewed changes, malformed content and wrong supplied canonical IDs return unavailable-content before checking a response.

Response maps are keyed by unique item/slot IDs; arrays of duplicate key pairs are not valid maps. Duplicate sequence IDs, unknown item/group/tile/option IDs, wrong kind/type, hidden/extra fields or sparse arrays return invalid-response. Missing keys and explicit null map entries, or a valid distinct partial tile sequence, return incomplete. Invalid values take precedence over omissions elsewhere. Complete in-domain wrong responses return judged false with the precise primary identity and a factual mismatch observation, without diagnosing a learner. No arbitrary text, case folding, trimming, substring match or universal category lookup exists.

The suite exhausts full domains against its own literal oracles, tests malformed/partial responses and content, preserves repeated-word occurrence identity, verifies metadata and binding counts, and reruns reconstructed/reordered/revised records against the same independent judgments. The two-stage relation and sentence-order cases include grammatically plausible wrong meanings.

## Hints, support and narration

Every record has two conceptual hints and a separately flagged worked example. Hints direct attention to context, clause scope or grammatical function without listing the item mapping, option ID or complete answer order. Worked support deliberately supplies an answer and explains it; explanations also remain answer-relevant post-Check/help content.

`instructionText` and identical `narration.neutralText` contain only control directions. No task-specific reason, category assignment or answer is inserted. Ordinary instruction/control narration is not answer help. Every task allows assessed-text reading before Check as listening support: read the visible context, blanks, location labels and **all** requested options faithfully without expanding a blank, announcing a category, selecting a correct option or using answer-revealing emphasis. Do not turn a clause-tile preview into an automatic corrected sentence. For the gardener choice, read each supplied sentence consistently; do not explain its commas until explicit help or feedback. Standard pronunciation/prosody is permitted as assessed listening, not an answer hint.

Assessed-text narration sets the listening-supported evidence fact downstream but does not set answerHintUsed/workedSupportUsed or remove ordinary reward eligibility. Hint and worked support set their respective sticky answer-help flags even when evidenceMode remains independent because the child read the text. A mode label cannot erase those flags. The pure evaluator imports no state, reward, audio or UI and cannot certify real playback or saved help history.
