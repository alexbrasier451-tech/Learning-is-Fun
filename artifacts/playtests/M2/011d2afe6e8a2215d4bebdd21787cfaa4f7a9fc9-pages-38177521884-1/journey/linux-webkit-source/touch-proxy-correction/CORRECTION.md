This is explanatory current upstream source, not an assertion that the installed binary was built from this exact commit.

The replacement is a stricter observation of the actual input. Existing init instrumentation adds passive capture listeners for touchstart/end and pointerdown/up. It only records metadata; it does not prevent events, dispatch events, override navigator, alter input coordinates or issue another action. For the sole ordinary Help tap before profile input, the hard gate requires isTrusted:true and either an ordered single-touch start/end pair with the same identifier and coordinates, or an ordered pointerdown/up pair whose pointerType is touch and whose pointer ID and coordinates match. This occurs independently in each context. The native-touch-proof attachment includes raw maxTouchPoints, all observed events and both proof booleans before asserting. Native state also retains the events throughout the case. If neither pair is observed, the case fails as a native touch capability blocker; no mouse fallback exists.
